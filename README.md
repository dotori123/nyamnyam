# 냥냠냠 (NyamNyam) 🐱

> Cat food, remembered.

우리 고양이가 먹은 사료·습식을 기록하고 다시 찾아보는 모바일 우선 웹앱.

- **스택**: React 19 + TypeScript + SCSS, Vite
- **현재 단계**: 구글 로그인 + **Firestore 동기화**. 로그인하지 않으면 이 기기에만 저장
- **배포**: https://nyamnyam-1fe27.web.app (Firebase Hosting)
- **예정**: 사진 Storage 업로드

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # tsc -b && vite build (PWA 매니페스트/서비스워커 포함)
npm run preview
npm run lint
npm run icons    # PWA 아이콘 PNG 재생성
npm run deploy   # 빌드 + Firebase Hosting·Firestore 규칙 배포
```

## 데이터 구조

`src/types/record.ts`의 `FeedRecord`와 `src/types/cat.ts`의 `Cat`이
그대로 Firestore 문서가 됩니다.

```
users/{uid}
  ├── cats/{catId}        → Cat
  └── records/{recordId}  → FeedRecord
```

설계 규칙:

- 중첩 배열을 쓰지 않음 (Firestore 미지원)
- `undefined` 대신 `null` (Firestore는 undefined 저장 불가)
- 날짜는 앱에서 ISO 8601 문자열, 저장 시 converter가 `Timestamp`로 변환
- 검색·필터 대상(`brand`, `flavor`, `foodType`, `rating`, `tags`, `catId`)은 문서 최상위에 평평하게
- 기록은 `catId`로 고양이를 참조합니다. 미지정이면 `null`

## 번들 — 무엇을 미리 싣는가

firebase가 들어오면서 첫 화면 번들이 285KB → 858KB로 뛰었습니다.
지금은 **Firestore만 떼어내** 418KB(gzip 128KB)로 돌려놨습니다.

| 언제 받는가 | 무엇 | 왜 |
| --- | --- | --- |
| 첫 화면 | React, 라우터, `firebase/app`, `firebase/auth` | 로그인 상태를 알아야 어느 저장소를 볼지 정해진다 |
| 로그인한 뒤 | `firebase/firestore` (555KB) + 변환기 | 로그아웃 상태로 쓰는 사람은 아예 내려받지 않는다 |

- `src/firebase/records.ts`·`cats.ts`는 **firestore를 정적으로 import하지 않습니다.**
  한 줄이라도 정적으로 부르면 첫 화면 번들에 그대로 딸려 들어갑니다.
  함수 안에서 `await import('firebase/firestore')`로 가져오고, 변환기도 같이 묶어 받습니다.
- 늦게 싣는 대신 **인증 확인이 끝나기 전에 로컬 기록이 잠깐 보였다 바뀌는** 문제가 생깁니다.
  그래서 지난번 로그인 여부를 이 기기에 남겨 두고(`nyamnyam.signedIn`),
  "로그인했었다"면 처음부터 계정 쪽을 봅니다 (`useAuth().expectsUser`).
- 불러오는 동안 목록은 `LoadingState`를 띄웁니다.
  이게 없으면 기록이 멀쩡히 있는 사람에게 "아직 기록이 없어요"라고 하게 됩니다.
- `vite.config.ts`의 `optimizeDeps.include`에 firebase 하위 경로를 못박아 뒀습니다.
  개발 서버가 화면을 그리다가 뒤늦게 발견하면 의존성을 다시 묶으면서
  페이지가 스플래시에 멈춘 것처럼 보입니다.

## 폼 검사 규칙

규칙 하나로 정리했습니다: **조용히 버리지 않는다.**

전에는 가격 칸에 `abc`를 넣으면 숫자가 아니라는 이유로 `0`이 저장됐습니다
(`Number('')`이 0이라서). 사용자는 값을 넣었다고 생각하는데 기록에는 다른 값이 남습니다.
지금은 읽을 수 없으면 저장을 막고 이유를 보여줍니다.

- 숫자 칸(가격·용량·체중)은 `12,900원`, `400 g`, `4.2kg`처럼 **사람이 쓰는 대로 넣어도 받아들이되**,
  숫자로 읽을 수 없거나 0 이하이면 오류입니다.
- 날짜 칸(구매일·생일)은 `max`로 달력에서 미래를 못 고르게 막고,
  **직접 타이핑한 경우도 제출 때 다시 검사**합니다.
- 저장이 막히면 **첫 오류 칸으로 포커스가 이동**하고 화면도 그리로 스크롤됩니다.
  화면 아래쪽 칸이 문제일 때 "왜 저장이 안 되지?"가 되지 않도록.
- 오류 칸은 `aria-invalid` + 빨간 테두리 + 칸 아래 문구 세 가지로 알립니다.
  문구는 `aria-describedby`로 입력칸과 이어져 있어 스크린리더가 함께 읽습니다.
  색만으로 알리지 않습니다.
- 다시 타이핑하기 시작하면 그 칸의 오류는 지웁니다.
- 오류 문구의 조사는 받침에 맞춰 고릅니다 (가격**을** / 용량**은** / 체중**을**).
  `utils/validation.ts`의 `withParticle`.

## 백업 (설정 → 백업)

계정 동기화가 붙기 전까지 기록은 이 기기 안에만 있습니다.
폰을 바꾸거나 브라우저 저장소를 비우면 사라지므로, 파일 하나로 담아 두고 되돌릴 수 있게 했습니다.

- **사진까지 한 파일에 담습니다.** 사진 빠진 백업은 백업이라 부르기 어렵습니다.
  Blob은 JSON에 못 담아서 base64(data URL)로 넣는데, 그만큼 파일이 커집니다(대략 원본의 1.37배).
  저장 전에 사진을 줄여 두는 것(`utils/image.ts`)이 여기서도 효과를 냅니다.
- **합치지 않고 교체합니다.** 같은 id가 섞이면 어느 쪽이 최신인지 알 방법이 없어서,
  "백업 시점으로 되돌린다"는 규칙 하나로 갑니다.
- **덮어쓰기 전에 파일을 먼저 읽어 검사합니다** — `app`/`version` 확인, 배열 여부,
  기록·프로필의 필수 필드. 잘못된 파일이면 아무것도 건드리지 않고 이유를 보여줍니다.
  통과한 뒤에도 "지금 N건을 지우고 파일의 M건으로 바꿉니다"를 확인받고 적용합니다.
- 적용 순서는 **사진 먼저, 목록 나중**입니다. 반대로 하면 사진이 없는 상태가 잠깐 보입니다.
- 참조가 끊긴 사진은 백업에 담지 않고, 파일 버전이 다르면 가져오기를 거부합니다
  (`BACKUP_VERSION`을 올리면 옛 파일이 자동으로 걸립니다).

## 제품별 보기

이 앱을 쓰는 이유가 **"다음에 살 때 참고"** 라서, 같은 제품을 여러 번 산 기록이
시간순으로 흩어져 있으면 정작 필요한 걸 못 봅니다 —
*"이거 저번에 얼마였지, 어디가 쌌지, 애가 좋아했나"*.

- **기록 자체는 그대로 둡니다.** 같은 제품을 또 사면 기록은 2건이 맞습니다
  (가격도 구매처도 다르니까요). 묶는 건 **보여줄 때만** 합니다.
  덕분에 기존 통계·필터가 하나도 바뀌지 않았습니다.
- 무엇을 같은 제품으로 볼지: **브랜드 + 제품명**을 공백 정리하고 대소문자를 무시해 맞춥니다.
  "이나바 챠오"와 "이나바  챠오"를 다르게 세면 묶는 의미가 없습니다.
- **맛(flavor)은 일부러 키에 넣지 않습니다.** 참치맛과 닭고기맛은 보통 같은 제품 라인이라
  가격 비교에는 같이 놓고 보는 편이 쓸모 있습니다.
- 검색·필터·정렬은 두 보기가 **그대로 공유**합니다. 같은 목록을 다르게 보여줄 뿐입니다.
  정렬은 제품 묶음에도 같은 의미로 적용합니다 (가격순 → 100g당 평균 단가순,
  환산이 안 되는 개·팩 단위 제품은 항상 뒤로).
- 구매일을 안 적은 기록은 **기록한 날**을 대신 씁니다. 순서라도 맞아야 "최근"이 뜻을 가집니다.

## 통계 화면의 차트 규칙

숫자를 잘못 읽게 만드는 흔한 함정을 피하려고 몇 가지를 고정해 뒀습니다.

- **막대는 한 가지 색(`--primary`)만 씁니다.** 브랜드·사료 종류 비교는 "크기"가 답이라
  색을 나눌 이유가 없고, 색을 나누면 없는 분류가 있는 것처럼 읽힙니다.
- **재구매 의향만 상태색**(`--good`/`--warn`/`--danger`)을 쓰고, 항상 이모지·글자와 함께 둡니다.
  세 색을 누적 막대 하나에 붙이면 인접 대비가 기준(ΔE 15) 아래로 떨어져서
  (색각 이상이 아니어도 구분이 어렵습니다) 줄을 나눠 그립니다.
- **값은 막대 옆에 그대로 적습니다.** 툴팁이 값을 읽는 유일한 통로가 되면 터치 기기에서 못 읽습니다.
  월별 지출만 최고치 한 곳에 적고, 나머지는 **표로 보기**에서 전부 볼 수 있습니다.
- 막대는 24px 이하, 자라는 쪽 끝만 4px 둥글게, 기준선은 실선 헤어라인 한 줄.
- **단가 환산 규칙은 `utils/stats.ts` 한 곳에만** 둡니다
  (`unitPricePer100` = 무게·부피, `countPricePerItem` = 낱개).
  화면 표시용 `formatUnitPrice`도 이 값을 받아 문자열만 만듭니다 —
  환산이 두 군데 있으면 언젠가 어긋납니다.
- **낱개로 파는 제품은 개당(팩당) 가격으로 적습니다.** 습식·츄르는 원래 개수로 팔아서,
  무게로 환산이 안 된다고 빈칸으로 두면 정작 자주 사는 것들이 전부 비어 버립니다.
  "츄르 14개 12,900원 = 개당 921원"은 구매 판단에 그대로 쓰이는 값입니다.
- 다만 **단가 순위(통계)에는 무게로 환산되는 제품만** 넣습니다.
  원/100g과 원/개는 단위가 달라 한 줄에 세우면 비교가 아니라 착각이 됩니다.
  몇 건을 기준으로 센 것인지 화면에 적습니다.
- **배변 통계는 `모름`을 분모에서 뺍니다.** 모름은 좋지도 나쁘지도 않은 게 아니라
  *정보가 없는 것*이라, 정상으로 치면 신호가 묽어집니다.
  대신 분포 목록에는 무채색으로 함께 보여줘서 "기록이 부실하다"는 것도 보이게 합니다.
- **"배변이 안 좋았던 사료"는 분모를 항상 함께 적습니다** (`1/1건`).
  1건짜리 브랜드가 100%로 맨 위에 오면 사료를 억울하게 낙인찍는 셈이라,
  화면에도 "기록이 적으면 우연일 수 있어요"를 적어 뒀습니다.
- 필터(고양이 선택)는 **차트 위 한 줄에만** 둡니다. 카드마다 따로 두면 지금 보는 숫자가
  무엇에 걸린 값인지 알 수 없게 됩니다.
- 가격이 없는 기록은 지출 합계에서 빼고(0원으로 치면 평균이 왜곡됩니다),
  몇 건 기준인지 요약 칸에 함께 적습니다.

## 데이터 저장

저장 위치는 **로그인 여부**로 갈립니다. 화면 코드는 이걸 모릅니다 —
`RecordsProvider`/`CatsProvider` 안에서만 갈라지고, `useRecords()`/`useCats()` 인터페이스는 그대로입니다.

| 상태 | 기록·프로필 | 사진 |
| --- | --- | --- |
| 로그아웃 | 이 기기 (localStorage) | 이 기기 (IndexedDB) |
| 로그인 | Firestore `users/{uid}/...` (오프라인 캐시 켬) | **이 기기 (IndexedDB)** — 아직 Storage 미연동 |

- **로그인 중에는 localStorage를 건드리지 않습니다.** 계정이 비어 있을 때 로컬을 덮어쓰면
  아직 옮기지 않은 기록이 사라집니다. 옮기는 일은 사용자가 확인한 뒤에만 합니다.
- 로그인하면 화면 위에 **"이 기기의 기록을 계정으로 옮길까요?"** 배너가 뜹니다
  (`CloudSyncBanner`, `src/storage/cloudSync.ts`). 모달로 막지 않는 이유는
  옮기지 않고 그냥 쓰는 것도 정상적인 선택이기 때문입니다.
  **옮기기는 복사입니다** — 로컬 데이터는 지우지 않아서, 중간에 실패해도 원본이 남고
  로그아웃하면 그대로 다시 보입니다.
- 서버 데이터는 **uid와 함께** 들고 있습니다. 계정을 바꾸는 순간 이전 계정의 기록이
  잠깐 보이는 일이 없습니다.
- 사진은 아직 이 기기에만 있습니다. 그래서 **다른 기기에서 열면 사진만 빠진 기록**이 보입니다.
  `url`이 빈 사진은 아예 그리지 않습니다 — `<img src="">`는 브라우저가 현재 페이지를
  통째로 다시 내려받게 만듭니다.
- 정렬은 `createdAt` 내림차순 하나만 서버에 맡깁니다. 만족도순·가격순까지 서버에 맡기면
  조합마다 복합 색인을 만들어야 해서, 기록이 수백 건 수준인 지금은 화면에서 정렬합니다.

아래는 **로그아웃 상태(이 기기 저장)** 의 동작입니다.

| 무엇 | 어디에 | 왜 |
| --- | --- | --- |
| 기록·프로필 본문, 선택된 고양이 | localStorage (`nyamnyam.*.v1`) | 동기 읽기라 첫 렌더에 바로 보인다 (빈 화면 깜빡임 없음) |
| 사진(Blob) | IndexedDB (`nyamnyam` / `photos`) | localStorage는 5MB 남짓이라 사진을 넣으면 금방 터진다 |

- `URL.createObjectURL()`이 만든 blob URL은 탭을 닫으면 죽습니다.
  그래서 저장할 때는 `photo.url`을 비우고(dehydrate), 앱을 열 때 IndexedDB 원본으로
  blob URL을 새로 만들어 붙입니다(hydrate). 원본이 없으면 그 사진만 조용히 버립니다.
- 사진은 **고르는 즉시** 긴 변 1600px · JPEG 82%로 줄여서 저장합니다 (`src/utils/image.ts`).
  폰 사진 한 장이 3~8MB라 그대로 쌓으면 저장소가 금방 차고, 나중에 Storage 업로드 비용도 그대로 늡니다.
  실제로 3024×4032 / 1.7MB 사진이 1200×1600 / 373KB로 줄었습니다.
  아이폰 사진은 회전이 EXIF에만 적혀 있어서 `imageOrientation: 'from-image'`로 디코딩합니다.
  400KB 이하는 재인코딩해봐야 화질만 깎여서 건드리지 않고, 줄이는 데 실패하면 원본을 그대로 씁니다.
- 미리보기와 저장본이 **같은 Blob**입니다. 화면에서 괜찮아 보이면 저장된 것도 괜찮습니다.
- 폼을 취소해 버려진 사진은 다음 실행 때 `useStoredPhotoGc`가
  "살아있는 사진 id"와 대조해 한 번에 지웁니다.
- 저장된 게 **아예 없는** 첫 실행에만 `src/mock`의 샘플(기록 1건 · 고양이 1마리)로 시작합니다.
- 설정의 **기록 전체 지우기**는 키를 지우지 않고 **빈 배열을 씁니다.**
  지워 버리면 "저장된 게 없다"가 되어 다음 실행에 샘플이 다시 깔리는데,
  비우려고 누른 사람에게는 안 지워진 것과 같습니다.
  빈 배열은 "비어 있는 상태를 사용자가 골랐다"는 뜻이라 그대로 유지됩니다.
- 로그인 중이라면 **계정에 올라간 기록도 함께** 지웁니다.
  화면이 보고 있는 건 Firestore인데 로컬만 지우면 버튼을 눌러도 아무 일이 없어 보입니다.
  (털색 테마는 다른 키라 남습니다)
- localStorage·IndexedDB 접근이 막힌 환경(시크릿 모드 등)에서는 저장만 조용히 실패하고
  그 세션 동안은 메모리 상태로 정상 동작합니다.
- 키에 `v1`이 붙어 있어, 저장 구조가 바뀌면 버전만 올리면 옛 데이터가 자동으로 무시됩니다.

## 기능

- **고양이 프로필** — 사진, 이름, 생일(나이 자동 계산), 품종, 성별, 체중, 특이사항.
  여러 마리 등록 가능하고, 목록에서 "이 아이로 전환"하면 기록 등록 폼의 기본값이 됩니다.
- **등록 폼** — 어느 고양이인지 선택, 브랜드/제품명/맛/종류/용량, 만족도(하트 5),
  배변 상태, 재구매 의향, 가격·구매처·구매일, 사진, 메모, 태그.
  저장을 막을 땐 첫 오류 칸으로 포커스가 이동합니다 (→ [폼 검사 규칙](#폼-검사-규칙))
- **사진** — 촬영(`capture="environment"`)과 앨범 선택(`multiple`)을 별도 input으로 분리.
  원본은 IndexedDB에 남겨 새로고침 후에도 보이고, 취소한 미리보기 URL은 회수합니다.
  (→ [데이터 저장](#데이터-저장))
- **통계** — 요약 4칸(기록 수·평균 만족도·재구매 의향·총 지출), 브랜드별 평균 만족도 순위,
  사료 종류 분포, 재구매 의향 비율, **100g당 단가(싼 순)**, 배변 상태 분포,
  **배변이 안 좋았던 사료**, 최근 6개월 지출. 위쪽 한 줄에서 고양이별로 좁혀 봅니다.
- **수정·삭제** — 기록 상세에서 고치거나 지웁니다 (`/records/:id/edit`).
- **다시 기록** — 기록 상세의 "🔁 다시 기록"으로 같은 사료를 또 살 때 다시 타이핑하지 않습니다.
  제품·구매 정보(브랜드·제품명·맛·종류·용량·가격·구매처·태그·고양이)는 물려받고,
  **이번에 겪은 일**(만족도·배변·재구매 의향·메모·사진)은 비웁니다.
  구매일도 비웁니다 — 오늘로 채워 두면 틀린 날짜가 조용히 저장될 수 있어서요.
- **목록** — 카드 형태, 최신순·만족도순·가격순 정렬. 카드에 100g당 단가를 함께 보여줍니다
- **제품별 보기** — 목록 위 전환 버튼. 같은 제품(브랜드+제품명)을 한 장으로 묶어
  **구매처별 가격·최저가·평균 만족도·100g당 평균 단가**를 나란히 보여줍니다
- **검색/필터** — 제품명·브랜드·맛·구매처·메모·태그 통합 검색, 고양이/종류/브랜드/맛 필터
- **PWA** — `vite-plugin-pwa`(autoUpdate), 매니페스트 + 아이콘 + 오프라인 프리캐시
- **반응형** — 모바일 우선, 520px 앱 셸. 다크 모드는 `prefers-color-scheme` 대응
- **접근성** — 본문 바로가기 링크, 경로별 문서 제목 + 화면 전환 시 본문 포커스, 아이콘 버튼 이름표,
  만족도 하트는 `radiogroup`, 지출 그래프는 요약 이름표 + 표 보기,
  `prefers-reduced-motion`이면 전환 효과 제거

## 브랜드 · 테마

앱 색은 **고양이 털색 테마** 5개 중에서 고릅니다 (설정 → 고양이 털색 테마).

| id | 이름 | 성격 |
| --- | --- | --- |
| `calico` | 삼색이 | 크림 + 주황 + 검정 (기본) |
| `cheese` | 치즈 | 버터빛 크림 + 주황, 검정 없음 |
| `cream` | 크림 | 아이보리 + 살구빛 코랄 (유일한 파스텔) |
| `mackerel` | 고등어 | 은빛 회색 + 청회색 (유일한 쿨톤) |
| `tuxedo` | 턱시도 | 흰색 + 검정 모노톤 |

- 팔레트는 `src/styles/_themes.scss`의 `$themes` 맵 한 곳에 있습니다.
  테마마다 모드별 시드 6개(bg / surface / primary / primary-ink / ink / on-primary)만 정하면
  나머지 톤(면 색, 보조 텍스트, 테두리, 그림자)은 믹스인이 파생시킵니다.
  **테마를 추가하려면 맵에 항목 하나만 더 쓰면 됩니다.**
- 테마 CSS 변수는 `:root`뿐 아니라 `[data-theme]` 요소에도 걸립니다.
  덕분에 설정 화면의 테마 카드가 자기 안에서 그 테마 색으로 미리보기를 그립니다.
- 선택값은 localStorage(`nyamnyam.theme`)에 저장하고,
  `index.html`의 인라인 스크립트가 **첫 페인트 전에** 적용해 기본 테마가 번쩍이지 않게 합니다.
- 로고 마크(CatMark)도 `--mark-*` 변수를 써서 테마를 따라갑니다.
  단 파비콘·PWA 아이콘은 설치형이라 브랜드 고정색(삼색이)입니다.

### 기본 테마 — 삼색이

삼색이(calico) 3색이 전부입니다.

| 토큰              | 값        | 쓰임                 |
| ----------------- | --------- | -------------------- |
| `$color-cream`    | `#FAF7F2` | 배경                 |
| `$color-orange`   | `#F4A71A` | 포인트 (버튼·선택·로고) |
| `$color-black`    | `#26261F` | 본문 · 로고 얼룩     |

- 원색은 `src/styles/_tokens.scss`의 SCSS 변수 3개뿐이고,
  화면에 쓰이는 색(`--bg`, `--primary` …)은 `global.scss`에서 그 값을 받아 CSS 변수로 펼칩니다.
  **브랜드 색을 바꾸려면 토큰 파일의 세 줄만 고치면 됩니다.**
- `--on-primary`는 흰색이 아니라 블랙입니다. 오렌지 위 흰 글자는 대비 2.0:1로 읽히지 않고,
  블랙은 7.5:1이라 WCAG AA를 넘깁니다.
- 오렌지를 **글자색**으로 쓸 때는 `--primary-ink`(딥 앰버)를 씁니다.
  `#F4A71A`는 흰 배경 대비가 2.0:1이라 본문에 쓸 수 없습니다.
- 본문 폰트는 **Pretendard 가변 웹폰트**(`pretendard` 패키지의 unicode-range 분할본)를
  `src/main.tsx`에서 불러옵니다. 폰트 스택은 `$font-sans` 토큰 한 곳에 있습니다.
  woff2 92개(약 2.8MB)를 전부 프리캐시하지 않도록 `globPatterns`에서 빼고,
  실제 내려받은 구간만 `runtimeCaching`(CacheFirst)으로 캐시합니다.
- 로고 마크는 `src/components/common/CatMark.tsx`. 같은 도형이
  `public/favicon.svg`, `index.html`의 스플래시, PWA 아이콘(PNG)에 들어갑니다.
  아이콘 PNG는 `npm run icons`(의존성 없는 `scripts/generate-icons.cjs`)로 다시 만들 수 있습니다.
- 스플래시는 `index.html`에 인라인 스타일로 두어 번들 로드 전에 먼저 칠해지고,
  React 마운트 직후 `src/main.tsx`가 페이드아웃시켜 제거합니다.

`src/firebase/README.md`에 순서와 문서 구조를 정리해뒀습니다.
`RecordsProvider` / `CatsProvider`의 내부 구현만 교체하면 화면 코드는 수정할 필요가 없습니다.

## 배포

```
npm run deploy
```

빌드 후 Hosting과 Firestore 규칙을 함께 올립니다 (`firebase.json`의 대상).
규칙은 **저장소의 `firestore.rules`가 단일 출처**입니다 — 콘솔에서 직접 고치면
다음 배포 때 파일 내용으로 덮여 씁니다.

### 캐시 헤더 — 배포 사고가 나는 지점

| 경로 | Cache-Control | 왜 |
| --- | --- | --- |
| `/assets/**` | `max-age=31536000, immutable` | 파일명에 해시가 붙어 내용이 바뀌면 이름이 바뀐다 |
| 그 외 전부 | `no-cache` | HTML·서비스워커가 낡으면 **이미 지워진 자산 해시를 가리켜 화면이 깨진다** |

두 가지를 실제 응답 헤더로 확인하고 정했습니다.

1. **헤더는 '마지막에 맞는 규칙'이 이긴다.** 좁은 규칙을 먼저 두면 넓은 `**`가 덮어씁니다.
   그래서 `**`를 먼저, `/assets/**`를 나중에 둡니다.
2. **헤더 매칭은 리라이트 *전*의 요청 경로로 한다.** `/records/123`은 `index.html`을
   받으면서도 `/index.html` 규칙에 걸리지 않습니다. SPA 딥링크를 덮으려면 `**`가 필요합니다.

### 자동 배포 (선택)

`firebase init hosting:github` 를 실행하면 서비스 계정과 GitHub 시크릿을 만들고
워크플로 파일까지 써 줍니다. 브라우저 인증이 필요한 대화형 명령입니다.
혼자 쓰는 앱이면 `npm run deploy` 한 줄로 충분해서 아직 붙이지 않았습니다.
